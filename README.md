# Муушиг оноо бүртгэгч (Muushig Scorekeeper)

Монгол **Муушиг** хөзрийн тоглоомын оноо, боолт, эцсийн мөнгөн тооцоог бүртгэх, гар утсанд зориулсан PWA вэб апп.

- **Нэг төхөөрөмжийн горим** — нэг хүн бүх тоглолтыг бүртгэнэ. Интернэтгүй ажиллана.
- **Олон утсаар хуваалцах горим** — хөтлөгч тоглолт үүсгэж, бусад нь 6 оронтой код / QR-ээр нэгдэж, оноог шууд харна (Supabase Realtime).
- Яг **5 тоглогч** — 4 эсвэл 6 тоглогчтой тоглолт эхлүүлэх боломжгүй (UI, тооцооны модуль, өгөгдлийн сан гурван түвшинд шалгана).
- Тоглогчийн профайл, тоглолтын түүх, статистик, график, JSON/CSV экспорт, нөөцлөлт.

Технологи: React 19 · TypeScript · Vite · Tailwind CSS v4 · Zustand · React Hook Form + Zod · Recharts · Dexie (IndexedDB) · Supabase · Lucide · vite-plugin-pwa · Vitest.

## Дүрмийн таамаглал (заавал уншина уу)

Муушигийн дүрэм бүс нутаг, найз нөхдийн хүрээнд ялгаатай байдаг. Тиймээс апп ямар ч дүрмийг “цорын ганц зөв” гэж тулгахгүй — **бүх тусгай дүрэм тохируулгатай**, тоглолт бүр үүсэх үедээ дүрмийн **хуулбарыг (snapshot)** хадгална. Дараа нь тохиргоо өөрчилсөн ч өмнөх тоглолтын үр дүн өөрчлөгдөхгүй.

Анхдагч утгууд ба тэдгээрийн утга:

| Дүрэм | Анхдагч | Тайлбар |
|---|---|---|
| Эхлэх оноо | 15 | Тоглогч бүр 15 онооноос эхэлнэ |
| Нэг мөрийн оноо | 1 | Авсан мөр бүрд оноо 1-ээр буурна |
| Мөргүй торгууль | +5 | Тоглоод нэг ч мөр аваагүй бол +5 |
| Сугарсны оноо | 0 | Тухайн тойрогт тоглоогүй (сугарсан) бол |
| Мөрийн нийлбэр шалгах | асаалттай | Тоглосон хүмүүсийн мөр нийлээд 5 байх ёстой |
| Гарах оноо | 0 | 0-д хүрсэн (доош орсон) тоглогч гарна |
| Дуусах нөхцөл | Эхэлж гарсан нь хожно | Эсвэл: “Сүүлд үлдсэн нь хожигдоно” |
| Боолтын үржвэр | ×2 | Тохируулж болно (1–10) |
| Боолт оноонд | асаалттай | Боолт хийсэн тоглогчийн тухайн тойргийн оноо ×2 (−2 → −4, +5 → +10) |
| Боолт мөнгөнд | асаалттай | Хожигдсон тоглогч боолт бүрдээ “Боолтын дүн”-г нэмж төлнө |
| Дөрвөн тамга | **унтраалттай** | Асаавал: нэг өнгийн 4 хөзөр барьсан тоглогч тухайн тойрогт шууд хожно |
| Гар засвар | асаалттай | Тойрог бүрт тоглогчийн оноог +/− гараар засах |
| Тооцооны арга | Гарааны бооцоогоор | Эсвэл “Онооны зөрүүгээр” (1 оноо = N ₮) |

**Боолт:** зөвхөн гараагүй, тухайн тойрогт тоглож буй тоглогч боолт хийнэ. Үржвэр тойрог хадгалахаас өмнө дэлгэц дээр тод харагдана. “Боолтын дүн” нь анхдагчаар `гарааны × (үржвэр − 1)` — ө.х. нэг боолт хийгээд хожигдсон тоглогч гарааны бооцоог **2 дахин** төлнө (5,000 + 5,000 = 10,000₮).

**Мөнгөн тооцоо:**
- *Эхэлж гарсан нь хожно* — хожигдсон тоглогч бүр `гарааны + боолтын дүн × боолтын тоо`-г хожигчид төлнө. Нэгээс олон хожигч тэнцвэл тэнцүү хуваана (₮-ийн үлдэгдэл алдагдахгүй).
- *Сүүлд үлдсэн нь хожигдоно* — сүүлд үлдсэн тоглогч бусад тоглогч бүрт мөн дүнг төлнө.
- *Онооны зөрүүгээр* — хос бүр онооны зөрүү × онооны үнээр тооцно.
- Дараа нь тооцоог **хамгийн цөөн шилжүүлэгт** буулгана (n−1-ээс ихгүй). Нийт цэвэр дүн үргэлж **Σ = 0** (тестээр баталгаажсан).
- Тоглолт дуусах нөхцөлд хүрээгүй үед “Тоглолтыг дуусгах” дарвал хамгийн бага (эсвэл их) оноогоор түр тооцож, үүнийг тодорхой анхааруулна. Тооцоо зөвхөн хэрэглэгч **баталгаажуулсны** дараа хадгалагдана.

Таны тоглодог дүрэм өөр бол **Тохиргоо → Анхдагч дүрэм** хэсэгт өөрчилнө үү.

## Архитектур

```
src/
  features/
    scoring/      engine.ts (цэвэр оноо тооцоолол), rules.ts, RulesEditor.tsx
    settlement/   settlement.ts (цэвэр мөнгөн тооцоо), SettlementView.tsx
    games/        gameOps.ts (immutable үйлдлүүд), gameRepo.ts, RoundForm.tsx
    players/      playerRepo.ts, PlayerForm.tsx
    statistics/   stats.ts
    multiplayer/  sync.ts (Supabase outbox/realtime), mapping.ts
  lib/            db.ts (Dexie), supabase.ts
  stores/         uiStore.ts (Zustand: toast, sync төлөв, тойргийн ноорог)
  hooks/ pages/ components/ types/ utils/
tests/            Vitest (unit + integration + component)
supabase/migrations/
```

- Бүх оноо, тооцооны томьёо `features/scoring` ба `features/settlement` дотор, React-аас тусдаа, тестлэгдсэн.
- Тойрог хадгалах бүрд IndexedDB-д шууд бичигдэнэ. Бөглөж буй (хадгалаагүй) тойрог ч localStorage-д хадгалагдана — хуудас refresh хийсэн ч алдагдахгүй.
- “Буцаах” нь сүүлийн 30 үйлдлийг (нэмэх/засах/устгах) буцаана.

## Supabase тохируулах (хуваалцах горим)

Supabase-гүй бол нэг төхөөрөмжийн горим бүрэн ажиллана; хуваалцах товч дээр тохиргооны заавар харагдана, апп унахгүй.

1. [supabase.com](https://supabase.com) дээр шинэ төсөл үүсгэнэ.
2. **SQL Editor** нээж `supabase/migrations/` доторх 3 файлыг **дарааллаар нь** (нэрийн дагуу) бүтнээр ажиллуулна.
   (Эсвэл Supabase CLI: `supabase link --project-ref <ref>` → `supabase db push`.)
3. **Authentication → Sign In / Providers → Anonymous sign-ins**-ийг идэвхжүүлнэ. (Тоглогчид бүртгэл үүсгэлгүйгээр нэгдэнэ.)
4. **Project Settings → API**-аас `Project URL` ба `anon public` түлхүүрийг авна.
5. Локалд: `.env.example`-г `.env` болгон хуулж утгуудаа оруулна. Vercel дээр: доорх env-ийг нэмнэ.

> ⚠️ `service_role` түлхүүрийг хэзээ ч `.env`/Vercel-ийн `VITE_` хувьсагчид бүү хий — `VITE_` угтвартай бүх зүйл хөтөч рүү очдог. Апп зөвхөн `anon` түлхүүр ашиглана.

Аюулгүй байдлын загвар:
- Бүх хүснэгтэд **Row Level Security** асаалттай. Зөвхөн тоглолтын хөтлөгч ба кодоор нэгдсэн гишүүд уншина.
- Клиент хүснэгт рүү шууд бичихгүй. Бүх бичилт `sync_game()` функцээр дамжих ба тэр нь дуудагч **хөтлөгч мөн эсэхийг**, **яг 5 тоглогч**, **тооцоо тэнцсэн** (Σ net = 0) эсэхийг шалгаж, нэг транзакцаар бичнэ.
- `version` баганаар хуучин (хоцорсон) илгээлт шинэ өгөгдлийг дарахаас сэргийлнэ; тойрог бүр клиент дээр үүссэн UUID-тэй тул давхар илгээлт давхар тойрог үүсгэхгүй.
- Офлайн үед өөрчлөлт `outbox`-д хадгалагдаж, сүлжээ сэргэхэд автоматаар (backoff-той) илгээгдэнэ. Үзэгчид дахин холбогдох, апп руу буцаж орох бүрд хамгийн сүүлийн төлөвийг дахин татна.

## Vercel-д гаргах

1. Энэ репог GitHub-д push хийнэ.
2. [vercel.com/new](https://vercel.com/new) → **Import Git Repository** → `muushig-scorekeeper`.
3. Framework: **Vite** (автоматаар таньна). Build: `npm run build`, Output: `dist` (`vercel.json`-д тохируулсан).
4. (Хуваалцах горимд) **Environment Variables**: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` → **Deploy**.
5. Env хувьсагчийг дараа нэмсэн бол **Redeploy** хийнэ (Vite эдгээрийг build үед суулгадаг).

`vercel.json` нь SPA routing (`/game/...`, `/join/...` шууд нээгдэх), service worker-ийн кэш толгойг тохируулсан.

## Хязгаарлалт

- Хуваалцах горимд **зөвхөн хөтлөгч** оноо оруулна; бусад нь шууд үзнэ. (Олон хүн зэрэг засах нь зөрчил үүсгэх тул зориуд хязгаарласан.)
- Тоглогчийн өөрийн зураг (photo avatar) зөвхөн төхөөрөмж дээр хадгалагдана; Supabase руу эмодзи орлуулагч очно.
- Төхөөрөмж хоорондын тоглогчийн жагсаалт/түүх автоматаар нэгтгэгдэхгүй — “Нөөц татах / сэргээх” ашиглана.
- Муушигийн дүрмийн ялгаатай хувилбаруудыг тохиргоогоор тусгасан ч бүх бүс нутгийн хувилбарыг хамарсан гэж баталгаажуулахгүй.
